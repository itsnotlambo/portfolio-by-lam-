Wordle AI Solver

A group project comparing search and machine learning on Wordle. I built the game state tracker that both solvers rely on.

Overview

For CS21002 Introduction to AI and Machine Learning, our group of four built a Wordle solver and compared two AI approaches: a search-based method and a machine-learning method. The comparison looked at success rate, average number of guesses and runtime.

My contribution: the game state tracker

I was responsible for the game state tracker, the part every solver depends on. It records what each guess has revealed and narrows the list of possible answers.

  • Designed the classes that hold the known letters, misplaced letters and excluded letters after each guess.
  • Filtered candidates with regular expressions over a dictionary of 616 verified five-letter words, rather than testing every combination by brute force.
  • Managed state between guesses so both solvers could share the same tracker.

Working in the team

Most of the group were new to Python, so I wrote heavily commented code and explained each section, so that everyone could understand and build on the shared foundation. That changed how I write code: readable for the least experienced person on the team comes first.

Evidence

The code lives in the group's private GitHub repository. I've kept this case study to my own part and haven't reported the group's final results here.
